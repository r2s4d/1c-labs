# Лабораторные по 1С:Предприятие 8.3 (конфигурация «МагазинАвтозапчастей»)

Репо: XML-выгрузка конфигурации (`config/`), задания (`materials/tasks/*.pdf`), лекции (`materials/lectures/*.pdf`) и генератор (`tools/labgen/`).
Платформа: 8.3.27, формат выгрузки 2.20. Язык кода и интерфейса: русский.

## Как устроена работа (главное правило)

XML и BSL лаб НЕ правятся руками. Всё в `config/` для лаб 2 и дальше создаётся генератором `tools/labgen/`.
Запуск: `python3 tools/labgen/run_all.py` (идемпотентный: те же UUID, можно запускать сколько угодно раз).
Если поправить файл в `config/` руками, следующий запуск генератора перезапишет правку. Чини ошибку в генераторе.

Двое исполнителей:
- **Агент-писатель (облако, нет платформы 1С).** Читает задание и лекцию, пишет батч генератора и проверочный BSL. Платформу не запускает, поэтому свою работу честно помечает «сгенерировано, не проверено».
- **Агент-отладчик (на компьютере Егора, есть платформа).** Подтягивает ветку, грузит в Конфигуратор базы «Лабы 1С», чинит ошибки платформы в генераторе, коммитит проверенное.

Статус лаб ведёт `tools/labgen/STATE.md`. Обновляй после каждой пачки.

## Git flow

- `main` не трогать. Проверенные лабы лежат в ветке `labs-claude`.
- Агент-писатель работает в ветке `labs-agent` (от `labs-claude`), один коммит на лабу: `Лаба N: что сделано (не проверено на платформе)`.
- Агент-отладчик после проверки коммитит в `labs-claude` с пометкой `(проверено на платформе)`.
- Пуши только по явной просьбе Егора. Не форсировать.

## Определение готовности (Definition of Done) для лабы

1. Прочитаны задание (`materials/tasks`) и лекция (`materials/lectures`), реализованы ВСЕ пункты задания, включая шаги про форму, подсистемы и командный интерфейс.
2. Есть батч `tools/labgen/batchN.py` и `Проверка_ЛабN(Лог)` в `tools/labgen/bsl/NN_labN.bsl`, которая выводит в лог данные, доказывающие результат (проведённые документы, остатки регистров, текст отчётов).
3. Тестовые данные вводятся кодом в `Заполнить_*(Лог)`, идемпотентно (через `НайтиСоздать`). Егор не хочет вводить данные руками.
4. `run_all.py` отрабатывает, `xmllint --noout` проходит по всем изменённым XML.
5. (Только отладчик) Загрузка без ошибок, «Проверка конфигурации» без ошибок, обновление БД, прогон дал `verify.txt` без строк `ОШИБКА`/`!!!`, результаты совпали с ожиданием из задания.

## Структура генератора (`tools/labgen/`)

- `labgen.py`: библиотека. `write/read`, `U(key)` (uuid5), `syn`, `human`, типы `t_ref/t_str/t_num/t_date`, `document_xml`, формы `document_form_xml`, `cfg_add` (добавляет объект в Configuration.xml в правильный порядок), `sub_content_add`, `ci_visible`, `ci_placement` (подсистемы), СКД `dcs_*`, `report_files`, табличный документ `sheet_xml`, `add_print_form`.
- `batch1.py` лабы 2-3, `batch2.py` лаба 4, `batch3.py` лаба 5. Новая лаба = новый `batchN.py`, добавить в `run_all.py`.
- `forms.py`: общее состояние форм документов `S`. Формы документов накапливают изменения от нескольких лаб, поэтому батч, который меняет форму, правит `forms.S[...]`, а `forms.write_forms()` вызывается один раз в конце. Такие батчи подключаются через `exec` в том же процессе (см. как подключён `batch3` в `run_all.py`).
- `bsl/NN_*.bsl`: куски временного общего модуля `ЗаполнениеДанных`. `build_data_module.py` собирает их и сам находит процедуры по шаблону `Процедура Заполнить_*(Лог)` и `Процедура Проверка_*(Лог)`. Сигнатура строго с одним параметром `Лог`.
- `05_report_helper.bsl`: `ТекстОтчета(ИмяОтчета, Параметры, ИмяМакета, ВариантНастроек)` выполняет отчёт на СКД и возвращает текст. Используй для проверки отчётов.
- Переменная окружения `INFOBASE_DIR` (по умолчанию `C:\Users\nikak\Projects\1c-labs-ib\`): каталог файловой базы, где лежат `run.flag` и `verify.txt`. `LABGEN_ROOT` меняет каталог `config`.
- Перед сдачей лаб временный модуль `ЗаполнениеДанных` и хук в `Ext/ManagedApplicationModule.bsl` нужно удалить (это сделает отладчик по просьбе Егора).

## Цикл проверки на платформе (только отладчик)

1. `python3 tools/labgen/run_all.py`, `xmllint`.
2. Конфигуратор базы «Лабы 1С»: Конфигурация, «Загрузить конфигурацию из файлов», каталог `config`, «Загрузить», «Да».
3. Конфигурация, «Проверка конфигурации», OK.
4. «Обновить конфигурацию БД» (F7).
5. Создать файл `run.flag` в каталоге базы, Отладка, «Начать отладку». Модуль сам прогонит заполнение и проверки, запишет `verify.txt`, удалит флаг и закроет клиент.
6. Прочитать `verify.txt`. Старый `verify.txt` удалить нельзя (нет прав), сравнивай время файла и строки «Старт/Конец».
7. Перед кликами в Конфигураторе делать скриншот, положение меню плавает. Не просить Егора трогать мышь во время прогона.

## Ловушки формата и платформы (уже наступали, не повторять)

Формат XML:
- Файлы: UTF-8 с BOM и CRLF. `labgen.write` делает это сам.
- Порядок в `Configuration.xml` ChildObjects строго по типам (`ORDER` в `labgen.py`). Добавляй только через `cfg_add`.
- Команда документа (`Command`) описывается ВНУТРИ XML документа в `ChildObjects` (с `uuid` и `Properties`). Отдельного файла `Commands/Имя.xml` быть не должно: ссылка `<Command>Имя</Command>` без тела даёт ошибку XDTO «Проверка дополнительного свойства». Рядом лежит только модуль команды `Commands/Имя/Ext/CommandModule.bsl`.
- Порядок в ChildObjects документа: Attribute, Form, TabularSection, Template, Command.
- У `DocumentJournal` нет свойства `FullTextSearch`. Ошибка «Свойство FullTextSearch не входит в состав объекта метаданных DocumentJournal».
- Табличный документ (макет `SpreadsheetDocument`). Образец формата бери у самой платформы: в проверочном BSL собери `ТабличныйДокумент` и сериализуй `СериализаторXDTO.ЗаписатьXML(Запись, ТабДок)` в файл, это точный формат `Template.xml`. Что так выяснили: тип заполнения ячейки (Параметр/Шаблон) хранится в формате `<format><fillType>Parameter</fillType></format>`, а ячейка ссылается на него через `<f>`; одного `<parameter>Имя</parameter>` без такого формата платформа читает как обычный текст (в BSL тогда «Поле объекта не обнаружено» у `Области.Параметры`). Ширина колонки в XML = символы x8. Индексы форматов 1-based. Ячейка строки это `<c><i>индекс</i><c><f>формат</f><tl>…</tl> или <parameter>Имя</parameter></c></c>`, то есть вложенный `<c>` внутри `<c>`. Плоская ячейка даёт «Форма: Элемент Тип: anyType» на свойстве `f`. Индекс колонки `<i>` не пишется для нулевой колонки.
- Команда формы для перехода к движениям регистра: `AccumulationRegister.Имя.StandardCommand.OpenByRecorder`. Вариант `OpenByValue.Recorder` не принимается («Неверное имя команды элемента формы»).
- Итог по колонке в подвале формы: путь данных подвала `Объект.ТабличнаяЧасть.TotalКолонка` (русское «ИтогСумма» в XML это `TotalСумма`), у таблицы `<Footer>true</Footer>`.

BSL и платформа:
- В общем модуле нельзя объявлять переменные на уровне модуля (`Перем Лог;` даёт ошибку проверки). Передавай `Лог` параметром.
- Нельзя вызывать метод у результата `Новый Класс(...)` цепочкой (`Новый Запрос(Т).Выполнить()` даёт «Неопознанный оператор»). Сначала переменная.
- У `Документы.Имя.Выбрать()` (выборка документов) нет метода `Количество()`. Для счёта документов используй запрос `КОЛИЧЕСТВО(*)`.
- Не называй вспомогательные процедуры именами, которые могут совпасть со встроенными или между кусками (`Записать` → `ЗаписатьЛог`, `Н` → `НомК`).
- Текст запроса в BSL: каждая продолжающая строка начинается с `|`.
- Клиентские вызовы с `&НаКлиенте`/`&НаСервере` писать как в учебных образцах из лекций (конструктор печати создаёт `ОбработкаКоманды` на клиенте и серверную процедуру в модуле менеджера).
- Документы для проверки создавай и проводи кодом (`Объект.Записать(РежимЗаписиДокумента.Проведение)`), потом читай регистры запросом.

## Ловушки лабы 16 (роли), проверено на платформе
- Права на `Enum.*` в Rights.xml вешают Конфигуратор намертво на этапе загрузки XML (процесс приходится снимать). В ролях объекты Enum не перечислять.
- Администратор с правом Delete получает и ИнтерактивноеУдаление, если явно не прописать `InteractiveDelete = false`.
- Нельзя `Если Новый Файл(...).Существует() Тогда`: цепочку через переменную (`Ф = Новый Файл(...); Если Ф.Существует()`).
- Зависание искать бисектом: пустая роль, потом по одному объекту. Перед каждым новым заходом процесс Конфигуратора надо снимать.
