# Лаба 16: роли, пользователи, интерфейсы

## Что сделано кодом (генератор `batch14.py`)
- Роли `Администратор`, `Директор`, `Мастер`, `Бухгалтер` с правами по условию задания (файлы `config/Roles/<роль>/Ext/Rights.xml`).
- Права на клиентские приложения (тонкий клиент и веб-клиент) у всех ролей, у Администратора ещё толстый клиент, внешнее соединение, автоматизация, администрирование.
- Справочники перенесены в подсистему `Предприятие` (она доступна всем ролям), журнал «Складские документы» добавлен ещё и в Бухгалтерию.
- Командные интерфейсы подсистем `УчетМатериалов`, `ОказаниеУслуг`, `Бухгалтерия`, `Предприятие`: команды разложены по группам панели навигации (Важное, Обычное, См. также) и панели действий (Создать), видимость задана по ролям.
- Проверка прав в `Проверка_Лаб16` (на несохранённых пользователях, ничего в базе не создаёт).

## Матрица прав
| Объект | Администратор | Директор | Мастер | Бухгалтер |
|---|---|---|---|---|
| Все объекты (кроме интерактивного удаления) | всё | просмотр | см. ниже | ввод, изменение, просмотр, пометка на удаление |
| Документ ОказаниеУслуги | всё | просмотр | ввод, изменение, проведение | только чтение и просмотр |
| Документ ПриходнаяНакладная | всё | просмотр | просмотр | ввод, изменение, проведение |
| Справочники Клиенты, Районы | всё | просмотр | ввод, изменение | ввод, изменение |
| Справочники Номенклатура, Сотрудники, Склады | всё | просмотр | только просмотр | ввод, изменение |
| Регистр сведений Цены | всё | просмотр | только просмотр | ввод, изменение |
| Подсистемы | все | все | ОказаниеУслуг, Предприятие | все |

## Видимость команд (по лекции 19)
- Движения регистров накопления (группа «См. также»): только Администратор и Бухгалтер.
- «Приходная накладная: создать», «Цена: создать»: только Бухгалтер.
- «Оказание услуги: создать»: только Мастер.
- Справочники: создание только Бухгалтеру (Клиенты и Районы ещё Мастеру); Директор видит списки Номенклатура, Сотрудники, Клиенты.

## Пользователи
Пользователи созданы в самой базе, а не в конфигурации, поэтому в `config/` их нет. Создать можно двумя способами:
1. Администрирование → Пользователи (как в лекции): Администратор (роль Администратор), Петров (Директор), Орлов и Волков (Мастер), Сидорова (Бухгалтер), аутентификация 1С:Предприятия, язык русский. Перед этим обновить конфигурацию БД (F7), иначе роли не появятся.
2. Кодом: положить файл `users.flag` рядом с файлом базы и запустить прогон проверки. После этого при запуске клиента появляется выбор пользователя; для служебного прогона запускать от имени Администратора.

## Что остаётся в Конфигураторе руками (начальная страница, пункт 4 задания)
Формы списка нужны явно (автоматические формы на начальную страницу ставить нельзя):
1. Форма списка документа ПриходнаяНакладная (колонка Склад), ОказаниеУслуги (колонки Склад, Клиент, Мастер), справочника Номенклатура (колонка ВидНоменклатуры), форма отчёта ВыручкаМастеров.
2. Корень конфигурации → «Открыть рабочую область начальной страницы», шаблон «Две колонки разной ширины (2:1)».
3. Мастер: слева список ОказаниеУслуги, справа Номенклатура. Бухгалтер: слева сверху ПриходнаяНакладная, снизу ОказаниеУслуги, справа Номенклатура. Директор: слева отчёт ВыручкаМастеров. Видимость каждой формы по ролям.
4. Основной раздел «Главное»: Мастер видит создание ОказаниеУслуги и отчёты Материалы, МатериалыНаСкладах, ВыручкаМастеров; Бухгалтер создание ПриходнаяНакладная и отчёты ВыручкаМастеров, РейтингУслуг, РейтингМатериалов, РейтингКлиентов, ЦеныНаУслуги; Директор отчёты РейтингУслуг, РейтингМатериалов, РейтингКлиентов.
5. Выгрузить конфигурацию и закоммитить результат (получится корректный XML для `Ext/HomePageWorkArea.xml` и формы списков).
